# CloudGIT

CloudGIT - это демонстрационное веб-приложение реализующее функционал удаленного GIT репозитория, с возможностью отправлять и скачивать данные по SSH (базовый функционал GitHub или GitLab).
Бэкенд, главным образом, состоит из 3-х сервисов реализованных на `Python`, и представляет из себя **асинхронные** `REST API` на `Django` (да, современные Django и DjangoORM могут в async), а также асинхронный SSH прокси сервер основанный на библиотеке [asyncssh](https://asyncssh.readthedocs.io/en/latest/#server-examples).
Для обмена сообщениями между сервисами разворачивается брокер `RabbitMQ`.
Фронтенд написан на `React` с использованием `MaterialUI` и самописным `ShadowRoot` компонентом для наиболее гибкой инкапсуляции стилей.

## Django Ninja или "FastAPI стайл"
Для роутинга, а также валидации и сериализации данных запросов используется асинхронная библиотека [Django Ninja](https://django-ninja.dev/motivation/) - более современный и асинхронный аналог `DRF`, основанный на `Pydantic`.
Стиль `Django Ninja` очень похож на `FastAPI`.
Здесь используются так называемые `Schema` - классы основанные на моделях `Pydantic` для сериализации данных, интегрированные с `DjangoORM`.

## Микросервисы
Основные `backend` сервисы написаны на Django в асинхронном стиле.
В качестве сервера для разворачивания Django приложения используется `Gunicorn` с воркерами `Uvicron`'а.

Все `backend` сервисы написанные на Python так или иначе используют следующий стэк:
- `Poetry` для управления зависимостями
- `Pydantic` для сериализация данных
- `aiohttp` для асинхронных запросов
- `aiopika` для асинхронного приема и отправки сообщений в `RabbitMQ`
- `asyncssh` для асинхронной отправки и проксирования входящих запросов по SSH

`Frontend` написан на `React`.
Сборка и отладка производятся с помощью `Vite`.
Роутинг реализуется с помощью data API и хука `useLoaderData`.
Реализуется компонент `ShadowRoot` для полноценной инкапсуляции стилей, поддерживающий `CSS` modules.
Основа интерфейса написана на "ванильном" React, но также используется `MaterialUI`, главным образом для отображения файловой структуры репозитория.

Далее перечисляются все сервисы и их назначения.

1. ### auth
Асинхронный REST API сервис на Django, для создания/удаления/аутентификации пользователя, а также для добавления SSH ключей в аккаунт пользователя для доступа к репозиториям.
Аутентификация происходит классическим способом, на основе `Cookie` и `CSRF` токенов.

2. ### repo
Асинхронный REST API сервис на Django, для создания/удаления репозиториев, для распределения добавляемых репозиториев в свободные хранилища, а также для получения из хранилища содержимого репозитория.

3. ### auth_db, repo_db
Сервисы разворачивающие базу данных `PostgreSQL` для обслуживания `auth` и `repo` соответственно.

4. ### sshproxy
Асинхронный сервис разворачивающий SSH прокси сервер.
Основывается на библиотеке `asyncssh`.
Его главная цель аутентифицировать пользователя по SSH ключам, валидировать и проксировать SSH соединение в хранилища для получения или отправки данных через `git`.

5. ### storage_n
Сервис имитирующий удаленное хранилище с функционалом `git` и `OpenSSH`.
Главным образом хранит пользовательские пустые (bare) `git` репозитории и посредством SSH соединения позволяет их обновлять.

6. ### frontend
Клиентское SPA на `React`.

7. ### rabbitmq
Сервис разворачивающий брокер сообщений `RabbitMQ`.

8. ### nginx, nginx-dev
Прокси сервер и распределитель нагрузки, для режимов запуска `demo` и `dev` соответственно.

## Как запустить?
**Замечание**: протестировано на `WSL2` (дистрибутив `Ubuntu` 24.04) и `Ubuntu` 25.04.

Необходимый софт:
- [Docker](https://docs.docker.com/engine/install/) + [Docker Compose](https://docs.docker.com/compose/install/)
- [OpenSSH](https://www.openssh.com/)

Для удобства демонстрационного запуска (ровно, как и для нужд разработки) приложения, все сервисы описаны в docker-compose файле и создан скрипт делающий остальную работу.

1. Клонировать репозиторий и перейти в папку `./cloudgit`:
~~~~shell
git clone --branch main --single-branch https://github.com/sammnnz/cloudgit.git
cd cloudgit
~~~~

2. Скопировать файл `.env` из папки `./example` в папку `./compose`:
~~~~shell
cp ./example/.env ./compose/.env
~~~~

**ВАЖНО**: для демонстрационного запуска (`demo` режим) необходимо освободить порты `81` и `23` (для прослушивания http и ssh соответственно).
Если нет возможности освободить `81` и `23` порты, то в файле `./compose/.env` нужно просто поменять порты на желаемые:

~~~~text
...
NGINX_HTTP_EXT_PORT=  # указать нужный порт вместо 81
NGINX_SSH_EXT_PORT=  # указать нужный порт вместо 23
...
~~~~

3. Запуск одной командой в режиме `demo`:
~~~~shell
./compose.sh -keygen demo up nginx
~~~~
Данная команда сначала генерирует (в папку ./_ssh) необходимые SSH ключи для работы хранилищ и SSH прокси сервера (при повторных запусках можно без флага `-keygen` если ключи уже сгенерировались).
Далее, указывается тип запуска (в данном случае `demo`) и передаются обычные аргументы для Docker Compose.
Команда `up nginx`, как следует из названия, билдит и запускает `NGINX` прокси сервер, а также все остальные сервисы (как зависимости).

**Замечание**: могут потребоваться привилегии для запуска скриптов `./compose.sh` и `./storages/utils/keygen.sh`, или для запуска Docker.
В таком случае, нужно дать соответствующие разрешения.
К примеру, на Ubuntu, это будет примерно так
~~~~shell
chmod +x ./compose.sh
chmod +x ./storages/utils/keygen.sh
sudo ./compose.sh -keygen demo up nginx
~~~~

4. Запуск в режиме `dev`:

**ВАЖНО**: для запуска в `dev` режиме необходимо освободить не только порты `81` и `23`, но и ряд других портов (`8000`, `8001`, `3000`, `5430`, `5429`, `33`, `5672`, `15672`, `2222`, `2223`), в зависимости от того, какие сервисы будут запущены.
Если нет возможности освободить нужные порты, то в файле `./compose/.env` нужно просто поменять порты на желаемые.
Также важно не забыть, для сервисов запускаемых на хост машине, прописать отдельные `.env` файлы согласующиеся с файлом `./compose/.env`.

Запускается командой вида
~~~~shell
./compose.sh -keygen dev up nginx-dev auth sshproxy ...
~~~~
В режиме `dev` сервис запускающий `NGINX` называется `nginx-dev`.
Он подтягивает за собой лишь сервисы `rabbitmq`, `storage_1`, `storage_2` и базы данных `auth_db`, `repo_db` для сервисов `auth` и `repo` соответственно.
Если требуется запустить еще какие-то сервисы (здесь, например, запускаются `auth` и `sshproxy`), то их названия также надо передать в команду.
Остальные сервисы могут запускаться локально для отладки, а `nginx-dev` обеспечит связь между сервисами, независимо от того находятся ли они в одной сети Docker или запущены на хост машине.

## После запуска
**ВАЖНО:** Далее предполагается что включен `demo` режим, а порты `81` и `23` в файле `./compose/.env` не изменялись.

**Замечание:** На данный момент реализован лишь базовый функционал, но для демонстрации основных возможностей этого хватит.

Необходимый софт:
- [OpenSSH](https://www.openssh.com/)
- [GIT](https://git-scm.com/downloads)
- Google Chrome / Safari / ...

1. В адресной строке браузера перейти по ссылке
~~~~text
http://127.0.0.1:81/
~~~~

Загрузится домашняя страница.

![](https://github.com/sammnnz/cloudgit/raw/main/example/1.png)

2. Нажав кнопку `signup` или перейдя по ссылке
~~~~text
http://127.0.0.1:81/signup
~~~~
нужно зарегистрироваться.

![](https://github.com/sammnnz/cloudgit/raw/main/example/2.png)

3. После регистрации, аккаунт будет доступен другим пользователям по ссылке вида
~~~~text
http://127.0.0.1:81/account/{username}
~~~~

4. На хост машине сгенерируем пару SSH ключей для удаленного доступа к репозиториям нашего аккаунта и добавим приватный ключ в ssh агент.
~~~~shell
ssh-keygen -t ed25519 -C "" -f ./ssh_key -N ""
eval "$(ssh-agent -s)"
ssh-add ./ssh_key
~~~~

5. Перейти в `Settings` аккаунта, либо по ссылке
~~~~text
http://127.0.0.1:81/account/{username}?tab=settings
~~~~
и добавить сгенерированный публичный SSH ключ (содержимое файла './ssh_key.pub').

![](https://github.com/sammnnz/cloudgit/raw/main/example/5.png)

6. Перейти в `Repositories` аккаунта, либо по ссылке
~~~~text
http://127.0.0.1:81/account/{username}?tab=repositories
~~~~
и создать репозиторий.

![](https://github.com/sammnnz/cloudgit/raw/main/example/6.gif)

7. На хост машине создадим репозиторий с веткой `main` и сделаем начальный коммит

**Замечание:** на данный момент еще не добавлена возможность выбора дефолтной ветки и переключения веток в "проводнике" (на странице репозитория), поэтому `main` пока что единственная поддерживаемая ветка.

~~~~shell
mkdir my-repo
cd my-repo
git init --initial-branch=main
echo "" > a.txt
mkdir fo && echo "" > ./fo/b.txt
git add .
git commit -m "Initial commit"
~~~~

8. Добавим remote origin и сделаем push в удаленный репозиторий
~~~~shell
git remote add origin ssh://{username}@127.0.0.1:23/{reponame}.git
git push --set-upstream origin main
~~~~

9. Теперь можно обновить страницу с репозиторием
~~~~text
http://127.0.0.1:81/account/{username}/{reponame}
~~~~
и увидеть изменения.

![](https://github.com/sammnnz/cloudgit/raw/main/example/9.png)

Без валидного SSH ключа, запушить изменения или клонировать репозиторий не получится (за это и отвечает сервис `sshproxy`).
